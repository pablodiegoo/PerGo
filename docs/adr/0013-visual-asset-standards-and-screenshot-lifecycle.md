# 0013. Visual Asset Standards and Screenshot Lifecycle

Status: accepted

## Context

PerGo is an open-source, self-hosted CPaaS platform providing unified messaging across WhatsApp Cloud (WABA), WhatsApp Web, Telegram, and webhooks. To communicate its technical maturity, architecture, and operator experience to open-source adopters, the project requires high-resolution UI imagery for its repository `README.md`, developer guides, and architecture documentation.

Previously, repository visual assets lacked standardized governance, posing four major challenges:
1. **PII and Credential Exposure Risk**: Capturing ad-hoc screenshots from active development or staging databases risks leaking real phone numbers, operator names, personal chat histories, or live Meta Graph API tokens.
2. **Viewport and Typography Fragmentation**: Visual assets captured on arbitrary screens (different retina scalings, ultrawide monitors, inconsistent aspect ratios) cause erratic layout density, unreadable text, and misaligned sidebars across documentation.
3. **Repository Bloat**: Uncompressed full-page PNGs (often 2–5 MB each) degrade Git clone speed and bloat historical repository size.
4. **Visual Drift and Obsolescence**: When Go Templ components (`templates/**/*.templ`) or Tailwind styles are updated, screenshots in documentation easily drift out of sync with actual software behavior unless tied to a formal review gate.

## Decisions

1. **Deterministic Mock Seeding via `cmd/pergo-seed`**: All public repository screenshots must be captured exclusively from deterministic mock fixtures generated by `cmd/pergo-seed`. The seed harness executes locally against PostgreSQL and requires zero external provider webhooks, live Meta tokens, or external API access.
2. **Strict PII Isolation**: Real customer data, personal phone numbers, and live secrets are strictly prohibited in all documentation assets. The seed harness establishes synthetic personas using reserved mock phone ranges (e.g. E.164 Brazilian test formats `+55 11 98XXX-XXXX` and North American `+1 555-0100..0199`), synthetic domains (`@mock.pergo.io`), and realistic Portuguese business conversation scenarios (onboarding questions, API tier inquiries, customer support dialogs).
3. **1440x900 Viewport Standardization**: All UI screenshots must be captured at a standardized desktop viewport of 1440x900 pixels (16:10 aspect ratio) at 100% zoom (1.0 device scale factor). This guarantees consistent sidebar ratios, data table column alignments, and message bubble aesthetics across all views.
4. **WebP/Optimized PNG Format and Compression**: Visual assets must be stored in modern WebP (`.webp`) format (quality 80–85) or crushed PNG (`oxipng` / `pngquant`). Individual image files must remain below 300 KB to avoid Git repository bloat while preserving sharp typography.
5. **Centralized Directory Structure**: All official platform screenshots are stored in `docs/assets/screenshots/` using standard kebab-case naming:
   - `inbox.webp` (Live Omnichannel Inbox with conversation thread and unread indicators)
   - `campaigns.webp` (Campaign Broadcaster with delivery statistics and recipient segments)
   - `connections.webp` (Channel connection manager showing WABA, WhatsApp Web, and Telegram)
   - `contacts.webp` (Contact list with multi-channel identities, tags, and custom attributes)
   - `templates.webp` (WABA message template manager with approved categories and quality scores)
   - `scalar-docs.webp` (Interactive Scalar OpenAPI 3.1 documentation explorer)
   - `dashboard.webp` (Operator dashboard, system overview, and telemetry)
6. **PR Lifecycle Gate**: Any pull request altering user-facing views (`templates/**/*.templ`, static CSS/JS, or admin navigation routes) must verify screenshot impact against `docs/assets/screenshots/`. The repository PR template includes an explicit check: `[ ] UI changed: screenshots updated according to docs/SCREENSHOTS.md`.

## Consequences

- **Guaranteed Privacy**: Complete immunity against PII leakage in public repositories.
- **Visual Uniformity**: Consistent visual language, viewport dimensions, and typography across all documentation.
- **Repository Efficiency**: Lightweight WebP assets minimize repository clone size and bandwidth consumption.
- **Maintenance Overhead**: UI refactors require contributors to re-run `cmd/pergo-seed` and capture refreshed screenshots following the standardized procedure.
