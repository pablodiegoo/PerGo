<objective>
Implement the ingestion-time pre-flight session window check in the outbound processor to reject expired non-template WABA messages with an HTTP 422 error before enqueuing.
</objective>

<tasks>

### Task 1: Add Session Window Check to Outbound Processor
<read_first>
- internal/outbound/processor.go
- internal/session/window.go
</read_first>
<action>
In `internal/outbound/processor.go` within `OutboundProcessor.Ingest` (after connection routing is resolved), add logic: if `conn.Channel == "whatsapp_cloud"` AND `req.TemplateName == ""` (meaning it's a freeform message), call `windowChecker.IsWindowOpen(ctx, workspaceID, req.To, "whatsapp_cloud", conn.SenderIdentity, 0)`. If the returned `WindowStatus.Open` is false, return a custom error (e.g., `*session.SessionWindowError`) containing the `WindowStatus` and `Source: "ingestion"`. You may need to create this custom error type in `internal/session/errors.go` or similar package if it doesn't exist.
</action>
<acceptance_criteria>
- `OutboundProcessor.Ingest` performs session window check only for `whatsapp_cloud` without a `TemplateName`.
- A 0-duration safety buffer is used.
- A custom error holding `WindowStatus` and source `"ingestion"` is returned when the window is expired.
</acceptance_criteria>
<verify>
grep -A 10 "conn.Channel == \"whatsapp_cloud\"" internal/outbound/processor.go
</verify>

### Task 2: Map Error to HTTP 422 in Message Handler
<read_first>
- internal/api/handler/message.go
</read_first>
<action>

Map this error to an HTTP 422 structured JSON response with code `"SESSION_WINDOW_EXPIRED"`, an appropriate message, and `details` containing `window_expired_at`, `window_duration`, `hint` ("Use type: template to reach this contact"), and `source`. Use the `domain.ErrorResponse` pattern.
</action>

</acceptance_criteria>
