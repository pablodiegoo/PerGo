- internal/domain/message.go
- internal/domain/event.go
</read_first>
<action>
Modify `internal/domain/message.go`:
1. Define message type constants:
   ```go

       MessageTypeProduct     = "product"
       MessageTypeProductList = "product_list"
   ```

<task id="T3" title="Implement Product Payload Validation Rules & Unit Tests">
<read_first>
- internal/domain/message.go
- internal/domain/message_test.go
</read_first>
<action>
1. In `internal/domain/message.go`, update `ValidateMessage(req *CreateMessageRequest)` to validate product payloads when `req.Type == "product"`, `req.Type == "product_list"`, or `req.Product != nil`:
   - Single product (`type: "product"`): verify `product_retailer_id` is non-empty.
   - Product list (`type: "product_list"`):
     - `1 <= len(req.Product.Sections) <= 10`.
     - Section title length <= 24 characters.
     - Total items across all sections <= 30.
     - Each item in sections must have a non-empty `product_retailer_id`.
   - If validation fails, append field-specific error details to `ErrorResponse` with code `"invalid_product_payload"`.
2. Create/update `internal/domain/message_test.go`:
   - Test single product validation passing and failing (empty SKU).
   - Test product list bounds (valid 2 sections 5 items, >10 sections failing, >30 total items failing, title >24 chars failing).
</action>
<acceptance_criteria>
- `ValidateMessage` enforces structural boundaries for single-product and product-list payloads.
- `internal/domain/message_test.go` exercises all valid and invalid boundary conditions with 100% test pass.
</acceptance_criteria>
<verify>
go test -v -race ./internal/domain/...
</verify>
</task>
