<objective>
Implement Meta Graph API interactive JSON formatting for outbound single-product (`type: "product"`) and multi-product list (`type: "product_list"`) messages, and map Meta catalog/SKU error codes (`131009` and `131084`) to terminal delivery errors.
</objective>

<tasks>

<task id="T1" title="Implement Interactive Product & Product List Payload Builders">
<read_first>
- internal/channel/whatsapp/waba.go
- internal/domain/message.go
</read_first>
<action>
Modify `WABAAdapter.Dispatch` in `internal/channel/whatsapp/waba.go`:
1. Add interactive product payload structures in `waba.go`:
   ```go
   type wabaProductAction struct {
       CatalogID         string             `json:"catalog_id"`
       ProductRetailerID string             `json:"product_retailer_id,omitempty"`
       Sections          []wabaProductSection `json:"sections,omitempty"`
   }
   type wabaProductSection struct {
       Title        string            `json:"title,omitempty"`
       ProductItems []wabaProductItem `json:"product_items"`
   }
   type wabaProductItem struct {
       ProductRetailerID string `json:"product_retailer_id"`
   }
   ```
2. In `Dispatch`, when `m.Product != nil` or `m.Type == MessageTypeProduct` / `MessageTypeProductList`:
   - Set `reqPayload.Type = "interactive"`
   - If single product (`type: "product"`):
     - `interactive.type = "product"`
     - `action = { catalog_id: m.Product.CatalogID, product_retailer_id: m.Product.ProductRetailerID }`
     - Set body and footer if provided.
   - If product list (`type: "product_list"`):
     - `interactive.type = "product_list"`
     - `header = { type: "text", text: m.Product.Header }` (if provided)
     - `action = { catalog_id: m.Product.CatalogID, sections: [...] }` with mapped `product_items`.
</action>
<acceptance_criteria>
- `WABAAdapter.Dispatch` correctly builds Meta interactive `product` and `product_list` JSON bodies.
- Section titles and product retailer IDs match the Meta Graph API spec.
</acceptance_criteria>
<verify>
go test ./internal/channel/whatsapp/... -run TestWABAAdapter_ProductPayloads
</verify>
</task>

<task id="T2" title="Map Meta Catalog & SKU Error Codes to Terminal Errors">
<read_first>
- internal/channel/whatsapp/waba.go
- internal/channel/channel.go
</read_first>
<action>
Update `WABAAdapter.classifyError` in `internal/channel/whatsapp/waba.go`:
1. Check for Meta Commerce error codes:
   - Code `131009`: Catalog ID invalid or not linked to WABA connection.
   - Code `131084`: Product SKU / Retailer ID does not exist in bound catalog.
2. Return `channel.NewTerminalError(err)` for codes `131009` and `131084` to halt worker retries immediately and record normalized delivery failure events.
</action>
<acceptance_criteria>
- Meta error code `131009` returns a `TerminalError`.
- Meta error code `131084` returns a `TerminalError`.
- Retries are prevented for missing catalogs and unlinked SKUs.
</acceptance_criteria>
<verify>
go test ./internal/channel/whatsapp/... -run TestWABAAdapter_MetaErrorClassification
</verify>
</task>
