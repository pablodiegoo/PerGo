<objective>
Implement synchronous pre-flight catalog and SKU validation during `POST /messages` ingestion, including resolution of `default_catalog_id` from connection settings, returning HTTP 422 for missing catalog IDs or invalid payloads prior to NATS JetStream queuing.
</objective>

<tasks>

<task id="T1" title="Catalog ID Resolution & Product Validation in Outbound Processor">
<read_first>
- internal/outbound/processor.go
- internal/channel/whatsapp/waba.go
- internal/domain/message.go
</read_first>
<action>
Modify `Processor.Ingest()` in `internal/outbound/processor.go`:
1. Define custom error variables/types in `processor.go`:
   - `ErrMissingCatalogID`: `errors.New("catalog_id is required for product messages and no default_catalog_id is configured for connection")`
   - `ErrInvalidProductPayload`: `errors.New("invalid product payload parameters")`
2. For product messages (`req.Type == "product"` or `req.Type == "product_list"` or `req.Product != nil`):
   - Resolve `catalog_id` following precedence (D-07):
     a) Explicit `req.Product.CatalogID` in request payload.
     b) Fallback to `default_catalog_id` in WABA connection credentials (`WABAConfig.DefaultCatalogID`).
     c) If both are empty, return `ErrMissingCatalogID`.
   - If fallback was used, set `req.Product.CatalogID = connConfig.DefaultCatalogID`.
   - Execute structural bounds validation (`domain.ValidateMessage(req)` or `domain.ValidateProductPayload(req.Product)`). If validation fails, return `ErrInvalidProductPayload`.
3. Pass resolved `Type` and `Product` payload into the published `QueueMessage`.
</action>
<acceptance_criteria>
- If `catalog_id` is missing in request and connection has `default_catalog_id`, it is auto-injected.
- If `catalog_id` is missing in both, `Processor.Ingest()` returns `ErrMissingCatalogID`.
- `QueueMessage` contains resolved product payload data.
</acceptance_criteria>
<verify>
go test ./internal/outbound/... -run TestProcessor_CatalogResolution
</verify>
</task>

<task id="T2" title="Map Ingestion Errors to HTTP 422 Responses">
<read_first>
- internal/api/handler/message.go
- internal/domain/message.go
</read_first>
<action>
Update `MessageHandler.Create` in `internal/api/handler/message.go`:
1. Inspect errors returned by `Processor.Ingest()`.
2. If the error is `ErrMissingCatalogID`, respond with HTTP 422 Unprocessable Entity:
   ```json
   {
     "code": "missing_catalog_id",
     "message": "catalog_id is required for product messages and no default_catalog_id is configured for connection"
   }
   ```
3. If the error is `ErrInvalidProductPayload` or contains validation details, respond with HTTP 422 Unprocessable Entity containing `invalid_product_payload` code and field-level details.
</action>
<acceptance_criteria>
- `POST /messages` returns HTTP 422 `missing_catalog_id` when no catalog ID can be resolved.
- `POST /messages` returns HTTP 422 `invalid_product_payload` when bounds checks fail.
</acceptance_criteria>
<verify>
go test ./internal/api/handler/... -run TestMessageHandler_ProductValidation
</verify>
</task>
