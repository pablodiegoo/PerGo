<objective>
Provide the cryptographic Data Exchange middleware to decrypt inbound flow data and encrypt dynamic flow responses via RSA-2048 and AES-128-GCM.
</objective>

<tasks>

<task id="T1" title="Implement Flow Cryptography Utilities">
<read_first>
- internal/platform/crypto/encrypt.go
</read_first>
<action>
Add functions `DecryptRSA(privateKeyPem []byte, ciphertext []byte) ([]byte, error)` using `crypto/rsa`.
Add `DecryptAES128GCM(key, iv, ciphertext, tag []byte) ([]byte, error)` and `EncryptAES128GCM(key, iv, plaintext []byte) ([]byte, []byte, error)`.
Implement an `InvertIV(iv []byte) []byte` function that performs a bitwise XOR of every byte with `0xFF`.
</action>
<acceptance_criteria>
- Utilities correctly decrypt Meta's sample Data Exchange payloads.
- `InvertIV` correctly flips all bits of the Initialization Vector.
</acceptance_criteria>
<verify>
go test ./internal/platform/crypto/... -run TestFlowCrypto
</verify>
</task>

<task id="T1b" title="RSA Private Key Secure Storage & Loading (D-05)">
<read_first>
- internal/platform/crypto/encrypt.go
- internal/repository/connection.go
</read_first>
<action>
Create `internal/platform/crypto/rsa.go` with:
1. `LoadRSAPrivateKey(connectionCredentials json.RawMessage, encryptor *Encryptor) (*rsa.PrivateKey, error)` — extracts `private_key` field from the WABA connection's credentials JSON (already AES-256-GCM encrypted at rest via `Encryptor.Decrypt`), then parses the PEM-encoded RSA key.
2. If `private_key` is not present in credentials, fall back to `os.Getenv("WABA_FLOWS_PRIVATE_KEY")` env var.
3. Validate the key is RSA 2048-bit; return error if key size doesn't match.
</action>
<acceptance_criteria>
- RSA key is loaded from encrypted connection credentials with AES-256-GCM decryption.
- Falls back to `WABA_FLOWS_PRIVATE_KEY` env var when credentials lack `private_key`.
- Returns error for non-2048-bit keys.
</acceptance_criteria>
<verify>
go test ./internal/platform/crypto/... -run TestLoadRSAPrivateKey
</verify>
</task>

<task id="T2" title="Data Exchange Handler">
<read_first>
- internal/api/handler/waba_webhook.go
</read_first>
<action>
Add an Echo handler in a new file `internal/api/handler/flow_data_exchange.go`:
`HandleFlowDataExchange(c *echo.Context) error` mapped to `POST /api/v1/waba/flows/data-exchange`.
1. Resolve connection from request context or query param.
2. Call `crypto.LoadRSAPrivateKey(conn.Credentials, encryptor)` to get the RSA private key (D-05).
3. Read the request JSON (`encrypted_flow_data`, `encrypted_aes_key`, `initial_vector`).
4. Decrypt the AES key via `crypto.DecryptRSA`.
5. Decrypt the flow data via `crypto.DecryptAES128GCM`.
6. Process the flow data (pluggable handler interface for dynamic screen content).
7. Invert the IV via `crypto.InvertIV`.
8. Encrypt the JSON response payload via `crypto.EncryptAES128GCM`.
9. Return the base64-encoded encrypted response to Meta.
</action>
<acceptance_criteria>
- The endpoint correctly responds to Meta's data exchange requests within the 15-second timeout window.
- The encrypted response is accepted by the WhatsApp client.
</acceptance_criteria>
<verify>
go test ./internal/api/handler/... -run TestHandleFlowDataExchange
</verify>
</task>

</tasks>
