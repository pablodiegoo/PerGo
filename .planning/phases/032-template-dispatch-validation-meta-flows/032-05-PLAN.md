<objective>
Decode completed Meta Flow submissions (`nfm_reply`) into structured webhook events and generate a formatted chat summary for the inbox.
</objective>

<tasks>

<task id="T1" title="Define flow.completed event type">
<read_first>
- internal/domain/event.go
</read_first>
<action>
Add `EventTypeFlowCompleted EventType = "flow.completed"` to `event.go`.
Define `FlowCompletedEvent` struct containing `Screen` (string), `Data` (map[string]interface{}), `FlowToken` (string), `ContactID` (string), and `Wamid` (string).
</action>
<acceptance_criteria>
- The new event type is available for the webhook system to broadcast.
</acceptance_criteria>
<verify>
go test ./internal/domain/... -run TestEventTypes
</verify>
</task>

<task id="T2" title="Two-stage JSON decoding for nfm_reply">
<read_first>
- internal/api/handler/waba_webhook.go
</read_first>
<action>
Modify `WABAWebhookHandler.HandlePost` inbound message parsing:
When `message.Interactive.Type == "nfm_reply"`:
1. Extract `nfm_reply.response_json` string.
2. Perform a second `json.Unmarshal` on `response_json` into a local struct (`flowResponse`).
3. Extract `flow_token` and `flow_data` (or `encrypted_flow_data` which gets decrypted if applicable).
4. Emit the `flow.completed` webhook event using the extracted payload.
5. Store a human-readable summary of the form submission in the Chat UI message bubble body.
</action>
<acceptance_criteria>
- Inbound flow completion webhooks are successfully parsed despite the nested stringified JSON.
- `flow.completed` events are fired correctly.
- The user's inbox shows a clear summary of the submitted flow data.
</acceptance_criteria>
<verify>
go test ./internal/api/handler/... -run TestWABAWebhook_NFMReply
</verify>
</task>

</tasks>
