<objective>
Implement synchronous pre-flight validation for template messages during `POST /messages` ingestion to reject invalid or unapproved templates before queuing.
</objective>

<tasks>

<task id="T1" title="Validate Template in Processor">
<read_first>
- internal/outbound/processor.go
- internal/repository/waba_template.go
</read_first>
<action>
Modify `Processor.Ingest()` to validate `req.TemplateName`:
1. Inject `WABATemplateRepository` into `Processor` (new field `templateRepo *repository.WABATemplateRepository`).
2. If `req.TemplateName != ""`, call `repo.GetByNameAndLanguage(ctx, conn.ID, req.TemplateName, req.Language)`.
3. If template is not found, return a strongly-typed `ErrTemplateNotFound`.
4. If template `Status != "APPROVED"`, return `ErrTemplateNotApproved` (include status and rejection reason).
5. **Normalize parameter formats (D-03):** Before count validation, detect whether `req.Components[i].Parameters` is provided as a positional array (`["John", "101"]`) or key-value map (`{"1": "John", "2": "101"}`). Add a `NormalizeTemplateParams` helper in `internal/outbound/template_params.go` that converts map format to ordered positional array by sorting keys numerically. After normalization, validate parameter count against the cached template's component variable count. Return `ErrInvalidTemplateParameters` if counts mismatch or character limits exceeded.
</action>
<acceptance_criteria>
- `Processor.Ingest()` correctly looks up the template in the repository cache.
- Strongly typed errors are returned for missing, unapproved, or misconfigured templates.
</acceptance_criteria>
<verify>
go test ./internal/outbound/... -run TestProcessor_TemplateValidation
</verify>
</task>

<task id="T2" title="Map Validation Errors to HTTP 422">
<read_first>
- internal/api/handler/message.go
</read_first>
<action>
Update `MessageHandler.Create` to inspect the error returned by `Processor.Ingest()`.
If the error is one of the new template validation errors (`ErrTemplateNotFound`, `ErrTemplateNotApproved`, `ErrInvalidTemplateParameters`), map it to an HTTP 422 response with a structured JSON body detailing the rejection reason.
</action>
<acceptance_criteria>
- `POST /messages` returns HTTP 422 for invalid templates instead of queuing them.
</acceptance_criteria>
<verify>
go test ./internal/api/handler/... -run TestMessageHandler_TemplateValidation
</verify>
</task>

</tasks>

<must_haves>
<truths>
- Meta API limits are protected by catching unapproved/invalid templates locally before API calls.
- Both positional array and key-value map parameter formats are accepted and normalized (D-03).
</truths>
</must_haves>

## Artifacts this phase produces
- `outbound.ErrTemplateNotFound` — custom error for missing templates
- `outbound.ErrTemplateNotApproved` — custom error for non-APPROVED templates
- `outbound.ErrInvalidTemplateParameters` — custom error for parameter count/format mismatch
- `outbound.NormalizeTemplateParams()` — normalizes array/map parameter formats to positional array
