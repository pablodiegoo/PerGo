## What was built
- Added `CountTemplateVariables` in `template_params.go` to parse `{{N}}` placeholders and extract expected variable counts from cached component JSON.
- Added `ValidateParameterCounts` in `template_params.go` to compare user-provided parameters against expected counts.
- Replaced the stub in `processor.go` with actual variable validation, ensuring parameter count mismatches are caught before being sent to the Meta API.
- Implemented comprehensive tests for parameter count extraction and validation.

## Files changed
- `internal/outbound/template_params.go` — Added `CountTemplateVariables` and `ValidateParameterCounts`.
- `internal/outbound/template_params_test.go` — Added tests for variable count logic.
- `internal/outbound/processor.go` — Replaced the placeholder stub in `Processor.Ingest()` to invoke the new validation logic.

## Tests
- `TestCountTemplateVariables` passes (validates counts across BODY, HEADER, and BUTTONS components).
- `TestValidateParameterCounts` passes (handles matches, mismatches, missing/extra components correctly).
- `TestProcessor` passes, ensuring the integration works with existing test suites.

## Decisions made
- The `CountTemplateVariables` method handles its own `json.Unmarshal` since it takes `json.RawMessage` directly, streamlining the processor ingestion logic.
- We issue a `slog.Warn` if `CountTemplateVariables` fails but do not block dispatch. This makes the validation resilient to any malformed cached data without dropping traffic.
