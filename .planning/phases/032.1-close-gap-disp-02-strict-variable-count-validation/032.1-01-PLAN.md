# Plan: Strict template variable count validation

<objective>
Replace the stub in processor.go (lines 246-252) with actual variable count extraction from cached template component JSON. Parse `{{N}}` placeholders from the `text` field of each component type (HEADER, BODY, BUTTONS) and validate that the user-provided parameter count matches.
</objective>

<tasks>

<task id="T1" title="Extract variable count from cached template components">
<read_first>
- internal/outbound/template_params.go (current normalization logic)
- internal/repository/waba_template.go (WABATemplate.Components field — json.RawMessage)
- internal/domain/message.go (TemplateComponent, TemplateParameter structs)
</read_first>
<action>
Add a function `CountTemplateVariables(components json.RawMessage) (map[string]int, error)` to `internal/outbound/template_params.go`:

1. Unmarshal the `json.RawMessage` into `[]map[string]interface{}` (Meta's component format).
2. For each component, extract the `type` field (HEADER, BODY, BUTTONS).
3. For HEADER and BODY: extract the `text` field, use `regexp.MustCompile(\{\{(\d+)\}\})` to find all `{{N}}` placeholders, count unique matches.
4. For BUTTONS: count the number of button entries that have `type: "URL"` with a `url` containing `{{1}}` (URL buttons with dynamic suffixes).
5. Return a map of component type → expected variable count (e.g. `{"BODY": 2, "HEADER": 1}`).

Also add a companion `ValidateParameterCounts(provided []domain.TemplateComponent, expected map[string]int) error` that:
1. For each entry in `expected`, find the matching type in `provided`.
2. Compare the length of `provided[i].Parameters` (after normalization) against the expected count.
3. If mismatch, return `ErrInvalidTemplateParameters` with a message like "component BODY expects 2 parameters, got 3".
4. If user provides a component type not in the template, warn but don't error (extra components are ignored by Meta).

Add tests in `internal/outbound/template_params_test.go`:
- Test `CountTemplateVariables` with a BODY containing `"Hello {{1}}, your order {{2}} is ready"` → expects `{"BODY": 2}`
- Test with HEADER + BODY + no variables → expects empty map
- Test with URL button containing `{{1}}` → expects `{"button": 1}`
- Test `ValidateParameterCounts` with matching counts → no error
- Test with mismatched counts → returns `ErrInvalidTemplateParameters`
</action>
<acceptance_criteria>

- All tests pass: `go test ./internal/outbound/... -run TestCountTemplateVariables`

</acceptance_criteria>
<verify>

</verify>
</task>
