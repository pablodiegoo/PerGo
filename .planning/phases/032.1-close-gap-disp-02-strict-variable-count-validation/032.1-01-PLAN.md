<objective>
Implement strict variable count validation for template dispatch to properly reject unexpected parameters and close the DISP-02 gap. The validation must fail if parameters are provided for a component that does not expect them, or if the template expects 0 parameters total but some were provided.
</objective>

<tasks>
<task>
  <read_first>
    - internal/outbound/template_params.go
  </read_first>
  <action>
    Update `ValidateParameterCounts(provided []domain.TemplateComponent, expected map[string]int) error` to strictly validate counts in both directions.
    1. Remove the `if len(expected) == 0 { return nil }` short-circuit.
    2. Build `providedCounts` map from `provided`.
    3. Loop over `providedCounts`. If `providedCount > 0`, verify `expectedCount := expected[cType]` matches. If not, return an error.
    4. Loop over `expected`. If `expectedCount != providedCounts[cType]`, return an error.
  </action>
  <acceptance_criteria>
    - `ValidateParameterCounts` returns an error if `provided` contains parameters for a component not present in `expected`.
    - `ValidateParameterCounts` returns an error if `provided` contains parameters when `expected` is empty.
  </acceptance_criteria>
  <verify>
    Run `go test ./internal/outbound -run TestValidateParameterCounts` (will fail until tests are updated).
  </verify>
</task>

<task>
  <read_first>
    - internal/outbound/processor.go
  </read_first>
  <action>
    Update `internal/outbound/processor.go` inside the `Process` method around line 245.
    Change the condition `} else if len(expected) > 0 {` to `} else {` so that `ValidateParameterCounts` is always called, even when `expected` is empty.
  </action>
  <acceptance_criteria>
    - `ValidateParameterCounts` is called unconditionally if `CountTemplateVariables` succeeds.
  </acceptance_criteria>
  <verify>
    Run `go build ./internal/outbound` to ensure it compiles.
  </verify>
</task>

    2. Add a new test case where `expected` is empty (`map[string]int{}`) but `provided` has a component with parameters, verifying it returns an error.
  </action>
  <acceptance_criteria>

  - A template expecting parameters for the BODY strictly rejects parameters provided for the HEADER.
  - Validation runs unconditionally for all template dispatches.
</truths>
