<action>
Update `internal/api/handler/waba_webhook.go`'s event switch statement to intercept `message_template_status_update` webhooks. Parse the `event` (e.g. APPROVED, REJECTED), `reason` (rejection reason), and `message_template_id`/`message_template_name`. Call `wabaTemplateRepo.UpdateStatus(ctx, templateID, status, reason, qualityScore)` to persist changes in DB and trigger the in-memory cache update. </action>
<acceptance_criteria>
  - `message_template_status_update` event correctly routes to processing logic
  - Webhook updates the template status and rejection reason in DB and cache
  - Quality score drops trigger structured logs and toast notification events
</acceptance_criteria>

### Task 2: Create Template CRUD & Sync REST Endpoints
<type>feature</type>
<files>
  - internal/api/handler/api/waba_template.go
  - internal/api/router/router.go
</files>
<read_first>
  - internal/api/handler/api/waba_template.go
</read_first>
<action>
Create `internal/api/handler/api/waba_template.go` to handle REST API endpoints. Implement `POST /api/v1/waba/templates` (Create), `GET /api/v1/waba/templates` (List), `GET /api/v1/waba/templates/:id` (Get), `PUT /api/v1/waba/templates/:id` (Update), `DELETE /api/v1/waba/templates/:id` (Delete), and `POST /api/v1/waba/templates/sync` (On-demand Sync). The `POST` and `PUT` handlers must use `WABAMetaClient` to submit to Meta Graph API immediately, then store the PENDING result in the repository. `DELETE` must invoke Meta API before removing locally. `POST /api/v1/waba/templates/sync` must invoke `WABAMetaClient.SyncTemplates` with 15-minute rate limiting enforcement. Register these routes in `internal/api/router/router.go`.
</action>
<acceptance_criteria>
  - Endpoints `POST`, `GET`, `PUT`, `DELETE`, and `POST /sync` are registered at `/api/v1/waba/templates`
  - `POST` / `DELETE` operations synchronously hit `WABAMetaClient` before DB modification
  - `POST /sync` invokes rate-limited template sync from Meta Graph API
</acceptance_criteria>
</tasks>
