<objective>
Update the API payload validation to allow connection slugs in the `channel` field (D-01) and update the `OutboundProcessor` to resolve connections using the slug cache before falling back to legacy default channels (D-02).
</objective>

<task id="03.1">
<title>Relax Payload Validation</title>
<type>code</type>
<read_first>
- internal/domain/message.go
</read_first>
<action>
Modify `ValidateMessage` in `internal/domain/message.go`.
Remove the strict validation block that checks if `req.Channel` is present in `ValidChannels`.
Because `req.Channel` can now be an arbitrary connection slug (like `"vendas-sp"`), we cannot validate it against a fixed static list. Wait, we should still ensure it's not empty. Remove the `!ValidChannels[req.Channel]` condition.
(Note: the same applies to `FallbackChannels`, though we may need to assume fallback channels are also either legacy or slugs).
</action>
<acceptance_criteria>
- `ValidateMessage` does not return an error for `req.Channel == "vendas-sp"`
- `ValidChannels` strict check is removed or bypassed for arbitrary strings
</acceptance_criteria>
</task>

<task id="03.2">
<title>Update Processor Routing</title>
<type>code</type>
<read_first>
- internal/outbound/processor.go
</read_first>
<action>
1. Update `RouteResolver` interface in `internal/outbound/processor.go` to include `GetBySlug(ctx context.Context, workspaceID uuid.UUID, slug string) (*repository.Connection, error)`.
2. In `Processor.Ingest`, implement the routing logic precedence (D-02):
   - First, check if `req.From` is present, attempt `GetBySenderIdentity`.
   - If `req.From` is empty, attempt `p.resolver.GetBySlug(ctx, workspaceID, req.Channel)`.
   - If `GetBySlug` returns `ErrConnectionNotFound`, fallback to `p.resolver.GetDefaultChannelConnection(ctx, workspaceID, req.Channel)`.
   - If both fail, return a `RouteError`.
</action>
<acceptance_criteria>
- `RouteResolver` interface includes `GetBySlug`
- `Processor.Ingest` attempts `GetBySlug` using `req.Channel`
- `Processor.Ingest` falls back to `GetDefaultChannelConnection` if `GetBySlug` fails with not found
</acceptance_criteria>
</task>

<verify>
Run unit tests for `outbound.Processor` ensuring that passing a valid slug in `req.Channel` resolves to the correct connection, and that passing a valid legacy channel falls back properly.
</verify>

<must_haves>
<truths>
- Users can send messages using `{"channel": "vendas-sp"}`.
- Legacy integrations sending `{"channel": "whatsapp_cloud"}` still work if a default connection exists.
</truths>
</must_haves>
