<objective>
Update the admin panel to automatically generate and assign slugs when a connection is created (D-03, D-04) and expose the generated slug in the UI.
</objective>

<task id="04.1">
<title>Auto-Generate Slugs on Connection Create</title>
<type>code</type>
<read_first>
- internal/api/handler/admin/device.go
</read_first>
<action>
Modify `Create` in `internal/api/handler/admin/device.go`.
1. After extracting `name` from the form, call `slug.Generate(name)` (from `internal/pkg/slug`) to create the base slug.
2. In order to handle collisions (D-04), implement a loop (or query the repository to find the next available suffix).
   - Alternatively, let the database `UNIQUE` constraint handle the fallback. Loop: `conn.Slug = baseSlug`, attempt `Create`. If it fails with a unique constraint violation on `idx_connections_workspace_slug`, increment a counter (`baseSlug-2`, `baseSlug-3`) and retry.
   - Or introduce a helper `h.Connections.EnsureUniqueSlug(ctx, workspaceID, baseSlug)` that checks for existence before calling `Create`.
3. Set the generated unique slug on the `Connection` struct before passing it to `Connections.Create`.
</action>
<acceptance_criteria>
- `DeviceHandler.Create` populates the `Slug` field of the `Connection`.
- Collisions on `name` in the same workspace result in appended suffixes instead of HTTP 500 errors.
</acceptance_criteria>
</task>

<task id="04.2">
<title>Display and Edit Slugs in Admin UI</title>
<type>code</type>
<read_first>
- templates/pages/devices.templ
</read_first>
<action>
Modify `templates/pages/devices.templ` (and its generated `_templ.go` via `templ generate` which should be handled by the executor).
1. In the `ConnectionTable` template, add a column or a badge for the Connection Slug. Display `conn.Slug` so operators know what string to pass in the API `channel` field.
2. Implement slug editing in the connection settings modal to satisfy decision D-05 (Users can edit slugs via the admin UI). Make the slug field editable when updating a connection.
</action>
<acceptance_criteria>
- The HTML output for the devices list table includes the connection slug.
- Users can edit the slug field in the admin UI.
- `templ generate` is run to apply changes.
</acceptance_criteria>
</task>

<verify>
Create a new connection in the admin UI via the browser (or cURL). Verify that the slug appears in the UI and that a duplicate name creates a suffixed slug.
</verify>

<must_haves>
<truths>
